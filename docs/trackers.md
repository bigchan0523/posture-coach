# 모션 트래커(나래트래커 / SlimeVR) 연동

PC 없이 **폰 앱이 트래커 6개를 직접 받아서** 뼈대를 만들고, 카메라와 같은 운동 판정 규칙으로 자세를 봅니다.

## 쓰는 법
1. **PC의 SlimeVR 서버를 끄세요.** 켜져 있으면 트래커가 PC에 붙습니다. 공식 SlimeVR 안드로이드 앱도 함께 켜면 안 됩니다 (둘 다 6969 포트를 씀).
2. 폰과 트래커를 **같은 와이파이**에 둡니다. 밖에서 쓰려면 폰 핫스팟 이름과 비밀번호를 트래커에 저장된 와이파이와 똑같이 맞추면 됩니다.
3. 앱 홈 → **측정 방법** → 트래커 화면을 엽니다.
4. **측정 방법**을 고릅니다.

   | 방법 | 설명 |
   |---|---|
   | 카메라 | 지금까지와 같습니다. |
   | 트래커 | 트래커만 씁니다. 폰은 아무 데나 둬도 됩니다. 하체 운동 9가지만 되고, 나머지 운동은 자동으로 카메라를 씁니다. |
   | 둘 다 | 카메라 화면에 트래커 뼈대를 겹쳐 하체를 정확하게 봅니다. 카메라에서 몸이 가려져도 트래커로 계속 잽니다. |

5. **부위 지정:** 부위마다 ‘찾기’를 누르고 그 부위의 트래커를 흔들면 자동으로 지정됩니다. 지정한 부위는 저장됩니다.
6. **보정:** 트래커를 몸에 붙인 뒤 보정합니다. 각 단계는 3초를 세고 진행됩니다.
   - **1단계:** 똑바로 서서 앞을 봅니다.
   - **2단계:** 무릎을 앞으로 내밀며 살짝 앉습니다.

   트래커를 붙이는 방향은 상관없습니다.
7. 운동을 시작합니다. 쉬는 시간에 똑바로 서서 1초쯤 가만히 있으면, 트래커 방향이 틀어진 것(드리프트)을 자동으로 다시 맞춥니다.

트래커로 되는 운동은 스쿼트, 런지, 사이드 런지, 데드리프트, 글루트 브릿지, 월싯, 하이니즈, 마운틴 클라이머, 레그 레이즈입니다. 팔에는 트래커가 없어서 팔 운동은 카메라를 씁니다. 카프 레이즈는 발 트래커가 있어야 합니다.

## 구조
```
트래커(ESP, 와이파이) ──UDP 6969──▶ native/android/SlimeServer.java  (SlimeVR 서버 대신 받는 부분)
                                     └ SlimeVRPlugin.java (Capacitor 플러그인, 초당 50번 JS로 전달)
js/trackers.js   보정 · 3D 뼈대 · 옆/정면 투영 → 카메라와 같은 33개 관절 좌표
js/engine.js     기존 YAML 운동 규칙 그대로 (트래커일 땐 정면·옆 규칙을 모두 적용)
js/trackers-ui.js 트래커 화면
```

### 통신 방식 (SlimeVR 펌웨어 기준)
SlimeVR-Tracker-ESP의 `src/network/connection.cpp`와 SlimeVR-Server의 `TrackersUDPServer.kt`를 바탕으로 했습니다.

- **서버 찾기:** 트래커는 1초마다 `255.255.255.255:6969`로 핸드셰이크(종류 3, MAC 주소와 펌웨어 버전 포함)를 보냅니다.
- **연결:** 서버가 `[3, "Hey OVR =D 5"]`(64바이트)로 답하면 연결됩니다.
- **패킷 모양:** 모든 패킷은 `int 종류 + long 패킷번호 + 내용`입니다. 빅엔디언을 씁니다.
- **회전값:** 종류 17에 `센서번호, 데이터종류(1), x, y, z, w(float), 정확도`가 담깁니다.
  - 옛 펌웨어는 1, 16, 23번을 씁니다.
  - 묶음 패킷은 100, 101번입니다.
- **연결 유지:** 서버가 3초 동안 아무것도 안 보내면 트래커가 연결을 끊습니다. 그래서 0.5초마다 하트비트(종류 1)를 보냅니다.
- **센서 정보:** 센서 정보(15)를 받으면 `int 15 + 센서번호 + 상태`로 확인 응답을 보냅니다.
- **브로드캐스트 수신:** 안드로이드에서는 `WifiManager.MulticastLock`을 잡아야 브로드캐스트를 놓치지 않습니다. 필요한 권한은 `CHANGE_WIFI_MULTICAST_STATE`입니다.

### 뼈대 계산
- **좌표 변환:** 펌웨어 쿼터니언은 z가 위인 좌표계입니다. x축으로 -90° 돌려서 y가 위인 좌표계로 바꿉니다. SlimeVR 서버의 AXES_OFFSET과 같습니다.
- **1단계 보정:** 그 순간의 쿼터니언 `q0`를 저장합니다. 이후 각 뼈의 회전은 `q · q0⁻¹`입니다. 월드 기준 회전이라서 트래커를 어떤 방향으로 붙였는지와 상관없습니다.
  - 다리 뼈 방향 = 회전 × 아래쪽
  - 몸통 뼈 방향 = 회전 × 위쪽
- **2단계 보정:** 허벅지가 수평으로 나간 방향을 몸의 앞쪽으로 정하고, 부위마다 저장합니다.
- **3D 뼈대:** 골반에서 시작해 뼈 길이를 이어 붙입니다. 뼈 길이는 SlimeVR 기본 체형과 비슷하게 잡았습니다. 판정은 비율만 쓰기 때문에 키 입력은 필요 없습니다. 높이는 알 수 없어서 가장 낮은 점을 바닥으로 둡니다.
- **2D 투영:** 3D 뼈대를 옆 평면이나 정면 평면에 투영해 카메라 관절과 같은 모양으로 만듭니다. 그래서 YAML 기준값을 그대로 쓸 수 있습니다.
- **3D로만 알 수 있는 값:** 무릎 모임(`left_knee_in`/`right_knee_in`)과 옆에서 본 엉덩이 각도(`front_hip_angle`)는 3D 뼈대에서 바로 계산합니다.

## 테스트
- `bash native/test/run.sh`: 수신기를 PC에서 컴파일하고 가짜 트래커 3개로 확인합니다. 가짜 트래커는 최신 펌웨어, 옛 펌웨어, 묶음 패킷 방식입니다.
- `node test/run.mjs`: 트래커 뼈대와 운동 판정을 확인합니다.
  - 가짜 트래커는 부착 방향과 몸 방향을 무작위로 정합니다.
  - 보정, 무릎·상체 각도 정확도, 드리프트 재보정, 9가지 운동 횟수, 무릎 모임을 봅니다.
- `?demo` 주소: 웹에서 가짜 트래커 6개로 화면 전체를 확인할 수 있습니다.

## 아직 실제로 확인 못 한 것
- 나래트래커 실물 연결. 펌웨어가 SlimeVR와 호환되면 그대로 됩니다. PC의 SlimeVR에서 잘 됐다면 호환됩니다.
- 실제 몸에서의 각도 오차와 드리프트 정도
